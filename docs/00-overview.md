# 00 · 背景、目标与价值判断

## 问题

DSH 已有内置上下文压缩（`@deepseek-ai/dsh-compaction-basic`）。它的触发点在
`agent/pre-step`：只要请求压力越过阈值，就在**下一步之前**立刻压缩，与对话进行到哪一步无关。
后果：

1. 可能在一次编辑、一次诊断、一条工具链的中间被强制重置；
2. agent 事先没有机会把决定、路径、下一步写进 docs；
3. 除自动压缩之外没有任何预警，agent 和用户都不知道"快到线了"。

## 目标

- agent 有**一个自己的工具**，可以在它认为合适的边界请求压缩。
- 压缩**不在回合中间执行**：请求只登记，回合结束后才真正压缩。
- 用户不需要手工算 token：默认策略从 DSH 自身配置推导。
- 当用户显式设了策略、而任务明显不匹配时，agent 能**向用户建议**调整，用户在对话里一键接受。
- 给 agent 的固定指令保持短，动态信息只在需要时出现。

## 非目标

- 不实现新的摘要器，不替换 `compaction-basic`。
- 不关闭、不接管内置自动压缩（它继续作为安全网）。
- 不改 Session 日志格式，不新增 event type。
- 不做全局（跨会话）阈值仪表盘。

## 核心洞察

**内置阈值并不"早"，而是"无意义"。** deepseek-flash 的窗口是 1,048,576，
按默认配置（ratio 0.8、headroom 64k、请求预留输出 256k）自动线落在
`min(838,860, 727,040) = 727,040`，约 **69%**、也就是 **72.7 万 tokens**。
这既是"非常晚"，又因为它只看 token 不看语义，所以经常在错误的时刻发生。

因此插件真正提供的价值按重要性排序：

1. **先落盘再压缩**：agent 有机会把决定与下一步写进 docs，摘要只作兜底。
2. **在边界压缩**：回合结束、阶段完成、切换子任务前，而不是工具链中途。
3. **预警**：在到达内置线之前提醒 agent，让它有时间收尾。
4. **可解释**：用户知道压缩为什么发生、释放了多少。

## 还需要这个插件吗？

诚实的判断：

- 如果你只想要"自动压缩"，**不需要**——DSH 已经有了。
- 如果你想要的只是"更早的阈值"，也**不值得**——那只是把同一个无意义的触发点提前。
- 这个插件值得做的前提是你认可第 1、2 条价值：**压缩的语义位置**与**压缩前的状态落盘**。
  否则内置压缩已经足够。

## 建议的最小形态

- 一个工具 `request_compaction`：登记请求，回合结束后执行。
- 一段 3–5 行的 static system prompt 指令（什么时候用、什么时候不用、压缩前做什么）。
- 一条按 DSH 自身配置推导的系统线：只在压力接近它、且回合结束时才真正花钱压缩。
- 一个全局默认阈值（插件设置页，默认 60%）与一个每会话覆盖（模型菜单里的一行），
  两者都用百分比，不用模式，也不用 token 数字。
- 不给 agent"建议改阈值"的能力：它判断不了这件事，容易把用户引向错误设置。
